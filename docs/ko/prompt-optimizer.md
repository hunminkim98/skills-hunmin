# prompt-optimizer

[English](../en/prompt-optimizer.md) · [문서 홈](README.md) · [SKILL.md](../../cursor/prompt-optimizer/SKILL.md)

거친 초안, 흐릿한 아이디어, 작업 설명 하나를 받아, 아무 채팅 모델에나 붙여 넣을 수 있는 **완성된 프롬프트**로 바꿉니다.

## 왜 만들었나요

"프롬프트 좀 다듬어 줘"에 대한 흔한 답은 템플릿입니다. 한가운데 `[여기에 제품 붙여 넣기]`가 남고, 나머지 일은 사용자에게 돌아옵니다. 보내기만 하면 되는 답을 원한 순간에는 쓸모가 없습니다.

이 스킬은 **완성된 사용자 메시지**를 만듭니다. 코드 블록을 복사해 Claude, Codex, Copilot, 그 밖의 채팅에 붙여 보내고 끝입니다. 시스템 프롬프트를 만질 필요도, API `effort`를 조절할 필요도 없습니다. 그 한 메시지가 일을 다 해야 합니다.

[meta-prompting](meta-prompting.md)의 엔진이기도 합니다. 그쪽은 이 최적화기를 돌린 뒤 Y/N에서 멈춥니다. 프롬프트만 필요하면 이 스킬을, 실행 전에 승인이 필요하면 meta-prompting을 쓰세요.

## 원리

두 규칙이 다른 모든 것보다 위에 있습니다.

**플레이스홀더 금지.** 대괄호 칸, `{topic}`, `<your_input>`, "나중에 채우세요"라는 빈 줄은 안 됩니다. 명사를 대괄호로 감싼 순간이 플레이스홀더이므로 다시 써야 합니다.

**항상 완성본을 냅니다.** 정직한 경우는 둘입니다.

- **Case A: 이미 내용이 있을 때.** 숫자, 메일, 오퍼, 제품 설명을 프롬프트 **안에** 넣습니다. 전체가 한 블록입니다.
- **Case B: 작업의 종류만 말했을 때.** 그래도 프롬프트는 완성입니다. *다음* 모델에게 빠진 입력을 물어보라고 하거나, "다음에 메일을 붙여 넣을 테니 이렇게 하라"고 적습니다. 템플릿을 고치라고 하지 않습니다.

그다음 요즘 채팅 모델이 읽는 방식에 맞춥니다. 할 일과 출력 형태를 앞에 두고, 제약이 있는 *이유*를 짧게 쓰고, "불릿 쓰지 마"보다 "흐르는 문단으로 써"가 낫습니다. 섹션이 여러 개일 때만 XML 태그를 씁니다. 긴 문서는 위, 질문은 아래. 실수가 비싼 답에는 마지막 점검 한 줄을 넣습니다.

채팅에 보여야 하는 것은 **펜스 코드 블록 하나**뿐입니다. "프롬프트입니다"도, 변경 설명도 없습니다. 블록 끝에는 받는 모델에게 천천히 생각하라는 한 줄이 있습니다. 무엇이 바뀌었는지는 나중에 물어보면 되고, 최적화기 출력의 일부가 아닙니다.

## 언제 쓰나요

작업의 답이 아니라 **다시 쓸 프롬프트**가 필요할 때 `/prompt-optimizer`를 씁니다.

예: "이 프롬프트 고쳐 줘", "더 좋은 프롬프트로", "메일 분류용 프롬프트가 필요해", 초안을 붙여 넣고 날카롭게 해 달라는 요청.

에이전트에게 일을 *시키려는* 때(코드 수정, 버그 조사, 위키 기록)에는 쓰지 마세요. 프롬프트를 실행하기 전에 Y/N이 필요하면 meta-prompting입니다.

## 설치

Agent 채팅이 아니라 실제 터미널에서:

```bash
npx skills add hunminkim98/skills-hunmin --skill prompt-optimizer --agent cursor
```

이 머신 모든 Cursor 프로젝트에 넣으려면 `--global`을 붙입니다. 대화형 피커는 [문서 홈](README.md)을 보세요.

## 사용 방법

1. 새 Agent 채팅을 엽니다.
2. `/prompt-optimizer`와 초안 또는 작업 종류를 적습니다.
3. 코드 블록 하나만 복사합니다.
4. 일을 시킬 채팅에 붙여 넣습니다.

초안이 한국어면 최적화 결과도 한국어입니다. 다른 언어를 요청하지 않는 한요. 마지막 "천천히 생각하라"는 그 언어에 맞춰도 됩니다.

빈칸을 나중에 채우지 않습니다. 꼭 필요한 것이 빠졌다면, 프롬프트 자체가 다음 모델에게 물어보라고 합니다.

## 한계

프롬프트 API를 부르지 않고 도구를 조정하지도 않습니다. meta-prompting에서 Y를 누른 경우가 아니면 최적화한 프롬프트를 실행하지 않습니다. 당신이 주지 않은 사실을 지어내지 않습니다. Case B에서는 그 질문을 다음 턴으로 미룹니다.
