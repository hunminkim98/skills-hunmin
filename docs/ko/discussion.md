# discussion

[English](../en/discussion.md) · [문서 홈](README.md) · [SKILL.md](../../cursor/discussion/SKILL.md)

정말 어려운 문제에서, 실제 전문가 하위 에이전트끼리 짧게 토론하고, 제약이 순위를 바꿀 때 당신에게 물은 뒤, 권고안 하나를 냅니다.

## 왜 만들었나요

많은 "패널" 스킬은 연기입니다. 한 모델이 상자 그림 안에 일곱 목소리를 쓰고, 이미 정한 뒤에 메뉴를 줍니다. 어떤 키트는 매 라운드를 `debate/` 폴더에 남깁니다. 비싸고, 읽기 어렵고, 건너뛰기 쉽습니다.

이 스킬은 토론을 **결정 도구**로 봅니다. 사회자(지금 대화 중인 에이전트)가 **진짜 병렬 하위 에이전트**를 띄웁니다. 그들은 서로 반박합니다. 선택지의 순위가 갈릴 때 당신을 끌어들입니다. 열 페이지짜리 연극이 끝난 다음이 아닙니다. 결과물은 권고안이지 대본이 아닙니다.

되돌리기 어렵거나 여러 영역을 가로지르는 선택에 씁니다. 아키텍처, 제품 제약, 만들까 살까, 안전이냐 속도냐. "Postgres 포트가 뭐야?"에는 쓰지 않습니다.

## 원리

**복잡한 문제만.** 답이 하나이거나 진실의 출처가 하나면 사회자가 그렇게 말하고 바로 답을 제안합니다. 오타나 파일 찾기에 패널을 열지 않습니다.

**실제 하위 에이전트, 목소리 연기가 아님.** 기본은 전문가 셋, 영역이 셋 이상일 때만 다섯. **한 번의** 병렬 Task 배치로 띄웁니다 (`generalPurpose`, 코드베이스 탐색이 분명하면 `explore`). 각자 할 일 하나, 편향 하나, 자기 주장을 한 번은 공격해야 합니다. 사회자가 한 답에 그들을 흉내 내지 않습니다.

**복제 금지.** 좌석은 영역이나 이해관계가 달라야 합니다. 필수: **전문가**(그 영역을 소유)와 **반대자**(유력안을 공격). 세 번째는 **운영**(비용, 시간, 되돌리기), 첫 영역을 거부할 수 있는 두 번째 전문가, 또는 구체적인 이해관계자 대리입니다. "비전" 좌석도, 별도의 종합자도 없습니다. 종합은 사회자 일입니다. [`references/roles.md`](../../cursor/discussion/references/roles.md)를 보세요.

**당신이 토론 안에 있습니다.** 1라운드 뒤, 빠진 제약이 순위를 바꾸면 사회자가 `AskQuestion`을 씁니다. 토론을 다 끝낸 뒤에만 묻지 않습니다. 빠질 것이 없어도 한 번은 묻습니다. 계속, 제약 추가, 또는 종료. 결정적인 질문 하나나 둘. 전문가가 적은 목록 전부를 넘기지 않습니다.

**사회자가 당신과 말합니다. 전문가는 말하지 않습니다.** 보이는 것은 좌석, 긴장, 질문, 권고입니다. 인용이 무게가 있을 때만 붙입니다.

**빈 타협 없음.** "둘 다 일리 있다", 맨 "경우에 따라 다르다"는, 결정 요인을 말하고 어느 쪽에 유리한지 밝히지 않으면 안 됩니다. 남은 충돌은 `contested`입니다.

**파일 쓰기 없음.** `debate/`도, HTML도, 위키도 없습니다. 결정을 나중에 남기려면 [wiki-for-llm](wiki-for-llm.md)입니다. 같은 요청에서 시키지 않는 한 구현을 시작하지 않습니다.

흐름:

1. 문제를 한 문장으로 고정하고 복잡도(이해관계자, 트레이드오프, 되돌리기)를 봅니다. 쉬워 보이면 `AskQuestion`으로 패널 또는 직접 답.
2. 전문가 3~5명을 앉히고 명단을 보여 줍니다. 좌석을 고르겠다고 하지 않는 한 승인을 기다리지 않습니다.
3. **1라운드:** 독립 브리프를 병렬로. 각자 경로, 근거, 자기 안에 대한 반론, 사용자에게 물을 질문 최대 둘.
4. **사용자 게이트:** 순위를 바꾸는 항목만 `AskQuestion`.
5. **2라운드:** 같은 전문가, 이번에는 남의 헤드라인과 당신 답. 수정하거나 고수하고, 무엇을 보면 철회할지 말합니다. 세 번째 라운드는 충돌이 아직 중요하고 당신이 계속을 골랐을 때만.
6. [`references/report-shape.md`](../../cursor/discussion/references/report-shape.md)로 보고한 뒤 `AskQuestion`: 종료, 한 라운드 더, 또는 구현으로 넘김.

전문가 프롬프트는 [`references/round-protocol.md`](../../cursor/discussion/references/round-protocol.md)를 따릅니다. 전문가는 읽고 검색할 수 있습니다. 레포를 고치면 안 됩니다. 유료 토론 제품은 필요 없습니다.

## 언제 쓰나요

유능한 두 사람이 갈릴 수 있고, 틀렸을 때 값이 클 때 `/discussion`을 씁니다.

사실만 필요하면 [deep-analyze](deep-analyze.md), 넓은 웹 조사면 [deep-research](deep-research.md), 프롬프트를 만들면, 작업 일지를 쓰면 이쪽이 아닙니다.

이 스킬은 **슬래시로만** 켭니다.

## 설치

```bash
npx skills add hunminkim98/skills-hunmin --skill discussion --agent cursor
```

프로젝트/전역은 [문서 홈](README.md)을 보세요.

## 사용 방법

1. 새 Agent 채팅.
2. `/discussion`과 결정 ("필터는 바꾸되 p75 필드 이름은 유지할까?").
3. 사회자가 "패널 vs 바로 답"을 주면 고릅니다.
4. 명단과 첫 긴장을 읽습니다.
5. 중간 질문에 답합니다. 그 답이 순위를 움직이게 되어 있습니다.
6. 권고, 왜 다른 안이 졌는지, 당신이 정한 제약, contested, 리스크를 읽습니다.

소설 길이의 속기록이 나오면 안 됩니다. 나오면 스킬을 안 지킨 겁니다.

## 다른 스킬과

- 싸움이 사실이면 먼저 [deep-analyze](deep-analyze.md).
- 가치 싸움 전에 바깥 웹이 필요하면 [deep-research](deep-research.md).
- 이 채팅 밖으로 결정을 남기려면 뒤에 [wiki-for-llm](wiki-for-llm.md).
- 패널을 열기 전에 브리프를 승인하려면 [meta-prompting](meta-prompting.md).

## 한계

병렬 하위 에이전트는 시간과 토큰을 씁니다. 간단한 조회에는 패널을 거절합니다. 전문가도 틀릴 수 있어서, 보고는 근거 또는 `unverified`를 보여야 합니다. 시키지 않으면 승자를 구현하지 않습니다. 해로운 이중 용도 주제는 한 문단으로 거절합니다.
